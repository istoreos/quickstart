# 局域网设备管理产品分析草稿

> 状态：历史需求分析输入；产品语义以 [当前唯一产品与领域基线](lan-device-management-product-architecture.md) 为准  
> 日期：2026-09-25  
> 目的：先确认用户需求、产品层级和功能归位，再设计低保真交互结构  
> 不作为开发依据：本文保留问题推导和用户需求层级，不覆盖当前基线

## 1. 草稿结论

用户进入局域网设备管理，不是为了理解或维护“静态租约、DHCP 标签、限速规则、防火墙规则”等技术对象，而是为了完成以下任务：

1. 看清有哪些设备连接了自己的网络；
2. 判断设备和网络是否正常；
3. 管理某一台设备怎样联网；
4. 让一组设备按统一规则自动运行；
5. 在必要时配置局域网基础能力；
6. 发生问题时定位原因并安全恢复。

静态地址、上网路线、限速、配额、浮动网关和审计都是满足这些需求的能力，不应被设计成同等重要、同时出现的产品入口。

建议以“设备”为唯一核心入口，以局部渐进披露组织信息：高频任务直接出现，低频设置进入二级入口，技术信息仅在异常或用户主动查看时出现。

## 2. 本轮要解决的问题

M11～M20 阶段曾形成三块并列区域，但仍存在以下认知负担：

- 新设备页面和经典设备列表并存，用户需要判断该去哪里操作；
- 地址预留、限速和断网仍保留独立列表或经典编辑器；
- 分组、单设备设置、流量额度和直接规则属于不同模型，最终生效关系不够直观；
- DHCP、网关、浮动网关和全局带宽与普通设备管理处于相近的信息层级；
- 能力状态、插件状态、识别依据和内部规则等低频信息占用了普通用户注意力；
- 同一台设备的多个设置分别保存，容易出现部分成功和多处状态不一致。

本轮产品设计的目标不是继续增加入口，而是把已有能力重新放回合适的用户需求层级。

## 3. 目标用户及使用情境

### 3.1 普通管理者

可能不理解 DHCP、网关或防火墙，希望快速知道：

- 哪些设备正在使用网络；
- 陌生设备是谁；
- 如何改名；
- 如何暂停某台设备联网；
- 如何让某台设备使用固定地址。

这是默认界面首先服务的用户。

### 3.2 有批量管理需求的用户

希望管理儿童设备、访客设备、IoT 设备等集合：

- 一组设备统一暂停联网；
- 设置每天或每周的上网时段；
- 统一限速或设置流量额度；
- 少数设备具有例外规则。

这些能力重要，但使用频率低于查看和管理单台设备。

### 3.3 网络能力管理者

理解主路由、旁路由、DHCP 和浮动网关，需要：

- 配置 DHCP 和默认上网路线；
- 管理本机、上级、旁路由、自定义和浮动网关；
- 设置总带宽与统计能力；
- 判断基础网络能力是否健康。

这类设置影响范围大、修改频率低，应进入受保护的低频入口。

### 3.4 排障用户

只在网络异常时需要：

- 判断地址冲突或网关不可达；
- 了解为什么策略未生效；
- 查看最近变更和浮动网关切换；
- 导出、恢复或检查配置；
- 查看原始识别证据和能力限制。

诊断信息应在出现问题时主动出现，正常情况下保持安静。

## 4. 用户需求层级

### 4.1 基础层：安全感与可信度

这是所有功能共同依赖的基础，不设计为单独页面。

用户需要相信：

- 保存不会造成不可预期的全网断开；
- “在线”“允许联网”“已生效”分别表达真实含义；
- 保存失败后原配置能够恢复；
- 不支持的功能不会被展示成可用；
- 家庭设备身份、名称和流量信息不会被上传。

产品要求：

- 高影响操作必须先预览影响范围；
- “配置已保存”和“终端已经生效”必须分开；
- 跨地址、路线、限速和权限的修改整体成功或整体回滚；
- 错误信息优先说明影响和处理办法，而不是内部错误码；
- 缺少插件或 Adapter 不得影响基础设备列表。

### 4.2 第一层：看清网络里的设备

这是最高频、覆盖面最广的核心需求。

用户问题：

- 谁连接了我的网络？
- 它现在在线吗？
- 它大概是什么设备、什么品牌？
- 它是否需要我处理？

默认设备列表展示：

- 设备备注名或安全回退名称；
- 品牌文字和通用设备形态；
- 在线、离线或从未上线；
- 主要地址；
- 有线、无线或未知接入；
- 当前速度；
- 简短的策略或异常摘要。

默认设备列表不展示：

- DHCP Hostname；
- 原始厂商全称和识别置信度；
- 历史地址；
- 内部规则、tag 或 option；
- Adapter、插件和采样实现状态；
- 审计详情。

### 4.3 第二层：管理一台设备

这是最重要的操作需求。

用户希望围绕同一台设备完成：

- 修改设备备注名和设备类型；
- 保留当前地址或指定地址；
- 选择上网路线；
- 暂停或恢复联网；
- 设置上传、下载速度；
- 查看实时和历史用量；
- 设置上网时段或流量额度；
- 理解最终生效结果。

这些操作不再分散到静态地址列表、限速列表和全局设置，而是统一归入设备详情。

设备详情建议包含四个产品区域：

1. **设备信息**：备注名、品牌、类型、在线状态、接入方式和当前地址；
2. **网络与上网**：地址获取、地址保留、上网路线及 DHCP Hostname 高级项；
3. **使用限制**：联网权限、限速、分组、时段和流量额度；
4. **用量与诊断**：实时速度、历史用量、生效状态、异常与诊断信息。

常用状态先以摘要展示，用户明确点击编辑后再出现表单。

#### 4.3.1 设备备注名与网络主机名必须分离

“设备名字”实际包含两个不同需求，不能共用一个字段：

- **设备备注名**是用户用来认设备的中文或 Unicode 名称，例如“客厅电视”“爸爸的电脑”；它保存到 Quickstart 独立的设备资料中，只影响产品显示；
- **网络主机名**是写入 DHCP/dnsmasq 的协议字段，只允许安全的 ASCII 单标签，例如 `living-room-tv`，不能写入中文、空格、点、下划线或控制字符。

产品默认只让用户编辑“设备备注名”。网络主机名放在“网络与上网”的高级项中，并明确提示“用于局域网名称解析，仅支持英文、数字和中间连字符”。

设备备注名不得自动转拼音后写入 DHCP，也不得因为用户设置了中文备注名而触发 dnsmasq reload。需要局域网名称解析的用户应主动设置独立的网络主机名。

当前代码已经具备这种分离基础：设备备注名保存到独立的 `/etc/quickstart/device-profiles.json`，DHCP Hostname 则由后端限制为 1～63 字节的 ASCII host label。后续统一设计必须保留这一安全边界。

#### 4.3.2 设备级上网路线是核心控制

把某台设备的网关指定为旁路由、浮动网关或指定 IP，不是普通高级设置，而是本产品区别于一般设备列表的重要能力。

用户真实目标是：

- 把代理、过滤、下载、DNS 或其他复杂工作交给另一台机器；
- 分担主路由的计算和网络处理压力；
- 让不同设备选择不同的网络处理节点；
- 使用浮动 IP，在旁路由异常时自动切换到备用节点；
- 不改变整个家庭网络，只调整指定设备。

因此“上网路线”在设备详情中保持高可见摘要：

```text
上网路线：跟随网络默认
```

当设备使用非默认路线时，设备列表也应显示简短标签，例如“经旁路由”或“经浮动网关”；使用默认路线时不增加列表噪音。

用户可选择：

- 跟随网络默认；
- 本机路由；
- 上级路由；
- 旁路由；
- 浮动网关；
- 指定 IP。

保存后必须提示：这类设置通过 DHCP 下发，设备通常要重新联网或续租才会生效。当前实现还会同时把所选 IP 作为 DHCP 网关和 DNS 服务器下发；后续需要把 DNS 行为作为路线属性明确建模，默认隐藏，但不能在产品语义中悄悄绑定。

#### 4.3.3 设备图标使用自动推荐与用户覆盖

设备图标用于快速识别，不能与品牌和设备类型字段混为同一个值。建议使用以下优先级：

1. 用户手动选择的图标；
2. 自动模式下，已识别厂商对应的原创品牌视觉图标；
3. 无厂商图标时，使用设备类型图标；
4. 厂商和类型均未知时，使用通用电脑图标。

“识别到厂商优先”属于自动模式；用户明确选择图标后，手动选择始终优先，并提供“恢复自动推荐”。后续厂商或设备类型识别结果变化时，不覆盖用户选择。

编辑设备资料时展示：

- 当前图标及来源，例如“自动 · ASUS 厂商视觉”或“手动选择”；
- “使用自动推荐”；
- 按电脑、手机、影音、游戏、网络、智能家居和其他分组的图标库；
- 最近使用或当前类别优先，不把几十个图标一次无分组铺满。

厂商视觉资源必须是本项目原创或已获得明确授权的资产，不直接复制厂商商标、产品渲染图或第三方图标。普通界面继续用品牌文字表达准确厂商信息，图标只帮助快速扫描，不能代替品牌文字。

数据模型建议分离：

- `iconMode`：`auto` 或 `manual`；
- `iconKey`：手动选择或自动解析后的稳定资源键；
- `iconSource`：`manufacturer`、`device_type`、`fallback` 或 `user`；
- 厂商、设备类型和用户覆盖仍是三个独立事实。

#### 4.3.4 可选能力缺失时局部降级

浮动网关和 IP 限速依赖可选组件。某项能力没有安装、没有启用或运行异常时，不能让整个“网络与上网”或“使用限制”页面无法继续。

统一处理规则：

| 能力状态 | 产品表现 |
| --- | --- |
| 可用 | 正常编辑、预览和保存 |
| 已安装但未启用 | 保留入口，说明影响并提供“启用” |
| 未安装 | 仅锁定依赖该能力的选项，提供“了解并安装” |
| 状态异常 | 保留已有配置和只读结果，提供重试与诊断，不允许新应用 |
| 当前固件不支持 | 解释限制和替代方案，不展示虚假的安装按钮 |

具体行为：

- 浮动网关未安装时，其他默认、本机、上级、旁路由和指定 IP 路线仍可选择；浮动网关选项显示“需要安装”，用户主动选择时再进入能力说明；
- IP 限速未安装时，联网权限、设备分组、上网时段和不依赖限速的能力仍可编辑；只有上传、下载限速字段不可用；
- 已有设备引用缺失的浮动网关或限速能力时，保留用户期望配置并显示“当前无法执行”，不得静默删除、改为默认路线或假装已生效；
- 用户修改了不可用能力时，保存预检必须阻止该项，并允许用户安装能力或移除该项后继续；不得静默部分保存；
- 能力安装或启用过程保留当前编辑草稿，完成后返回原位置；失败时不应用其他修改；
- 普通文案使用“浮动网关能力”“设备限速能力”，组件包名只在安装确认或专家诊断中出现。

当前代码已经能返回 `available`、`disabled`、`not_installed` 和 `error`，且策略写入会拒绝未安装依赖。后续需要把这些状态整合成统一的能力契约和一致的就地交互，而不是由各页面分别判断插件状态。

### 4.4 第三层：批量管理与自动化

该层解决“管理一组设备”和“让规则自动执行”。

用户目标包括：

- 儿童设备在固定时段暂停联网；
- 访客设备统一限速；
- IoT 设备统一使用指定上网路线；
- 一组设备共享流量额度或用量策略；
- 少数设备设置明确例外；
- 一次批量调整多台设备。

建议将这一层称为“分组与计划”或“自动管理”，而不是“网络规则”。

主要内容：

- 全局默认；
- 设备分组；
- 定时计划；
- 流量额度；
- 单设备例外；
- 当前生效结果及来源解释。

普通用户看到的是结果，例如：

> 儿童设备 · 4 台 · 工作日 22:00 至次日 07:00 暂停联网

只有展开说明时才显示“全局默认 → 设备分组 → 单设备例外”的来源链。

### 4.5 第四层：局域网基础能力

这类设置非常重要，但修改频率很低，不应持续占据默认页面。

包含：

- DHCP 与地址池；
- 默认上网路线；
- 本机、上级、旁路由、自定义和浮动网关；
- 浮动网关节点与健康状态；
- 总上传、下载带宽；
- 流量统计来源和可选增强能力；
- 通知与策略备份。

建议使用“局域网设置”入口，通过状态卡展示当前结果，点击设置后才出现配置表单。

示例：

> 地址分配：运行正常  
> 默认上网路线：本机路由  
> 已为 18 台设备分配地址

不在默认状态卡中显示 DHCP tag、option 3/6 或 UCI section。

需要区分两个层级：

- **为设备选择上网路线**属于第二层的核心设备控制；
- **创建、编辑和维护旁路由、浮动网关、指定 IP 等路线目标**属于本层的低频基础设置。

### 4.6 第五层：异常处理与专家诊断

这类能力仅在异常发生或用户主动进入高级区域时出现。

包括：

- 地址冲突；
- 网关不可达；
- 等待终端重新获取地址；
- 策略应用或回滚失败；
- 浮动网关切换和降级；
- 审计事件；
- 管理入口探测；
- Webhook；
- 策略导入与导出；
- 原始设备识别证据；
- 当前固件或 Adapter 的能力限制。

正常情况下不重复展示“运行正常”“插件未安装”等技术状态。用户尝试使用相关能力时，再解释依赖和限制。

## 5. 网关分流与旁路由角色分析

### 5.1 当前代码如何配置旁路由

现有“配置为旁路由”向导会：

- 把 LAN 配置为静态地址；
- 在 `network.lan.gateway` 设置上级路由；
- 在 LAN 上设置 DNS；
- 允许选择是否关闭本机 LAN DHCP；
- 允许开启 LAN NAT；
- 可选建立 LAN DHCPv6 客户端。

这是一组网络配置操作，没有持久化一个权威的“本机角色=旁路由”产品字段。

### 5.2 当前代码如何判断旁路由

设备管理代码读取 `network.interface.lan status`：如果 LAN 接口路由数组中的第一项是 `0.0.0.0/0`，就认为 LAN 存在上级网关，并将该网关保存为 `Nexthop`。

代码中的字段名是 `IsDefaultGateway`，但其实际语义更接近“默认路由是否位于 LAN 上”。当它为 true 时，代码注释将设备视为旁路由形态。

当前判断存在局限：

- 没有读取一个用户明确确认的运行角色；
- 只检查 LAN 路由数组第一项，而不是查找全部默认路由；
- 没有同时考虑 WAN 是否承载默认出口；
- 没有把“旁路由拓扑”和“是否提供 DHCP”分开；
- 特殊静态路由、多出口或手动配置可能被误判。

因此新产品不能直接依赖当前布尔值决定全部 UI。

截至 2026-09-25，测试机 `192.168.9.215` 的 LAN 未配置上级网关、LAN DHCP 正在运行，WAN 使用 DHCP；按当前配置它属于普通主路由形态，不是旁路由。该环境事实只用于验证当前行为，不作为产品角色判断规则。

### 5.3 当前旁路由形态带来的功能差异

当前设备管理逻辑大致表现为：

| 当前形态 | DHCP 状态 | 设备级指定网关 |
| --- | --- | --- |
| 普通主路由 | 本机提供 DHCP | 可指定本机、旁路由、浮动网关或自定义 IP |
| 旁路由 | 本机不提供 DHCP | 本机无法给终端下发设备级网关，当前后端会拒绝修改 |
| 旁路由 | 本机提供 DHCP | 可给终端分配本机、上级路由或其他路线 |
| 任意拓扑 | DHCP 被关闭 | 只能查看，不能通过本机应用设备级 DHCP 路线 |

关键结论是：决定设备级网关功能是否可用的，不只是“本机是不是旁路由”，而是“本机是否掌握这些设备的 DHCP 地址分配权”。

如果本机是旁路由且 DHCP 由主路由提供，那么应该在主路由上把目标设备的网关设置为这台旁路由，或者设置为两台节点共同提供的浮动 IP。旁路由自身无法通过本机 DHCP 修改这些终端。

### 5.4 新产品需要的路由器上下文

不建议继续使用单一 `isBypassRouter` 布尔值。建议由一个深 Module 统一计算并返回简洁的“路由器上下文”：

- **拓扑位置**：主出口路由、旁路由、无法确定；
- **DHCP 分配权**：本机负责、其他设备负责、状态异常；
- **本机地址**：可作为设备网关的 LAN 地址；
- **上级网关**：当前观察到的上级路由；
- **设备路线能力**：可配置、只读、需要先启用 DHCP；
- **浮动网关参与状态**：未配置、优先服务节点、故障接管节点；
- **判断依据和置信度**：只放在诊断信息中。

普通 UI 只消费“可配置哪些路线”和“为什么不可配置”，不理解 UCI、默认路由或 DHCP tag。

### 5.5 角色感知的产品表现

#### 本机是主路由且提供 DHCP

- 设备详情直接提供完整“上网路线”选择；
- 默认路线通常是本机；
- 可以新增旁路由、浮动网关和指定 IP；
- 这是设备分流功能的主要使用场景。

#### 本机是旁路由但不提供 DHCP

- 设备详情仍显示当前路线信息，但路线编辑为只读；
- 显示明确说明：“设备地址由主路由分配，请在主路由上将该设备的上网路线设为本机 IP”；
- 展示本机可被主路由使用的网关地址，提供复制；
- 不诱导用户在旁路由上启用 DHCP，避免局域网出现两个 DHCP 服务器；
- 未来可考虑主、旁路由配对管理，但不应在当前版本伪装为已经支持。

#### 本机是旁路由且提供 DHCP

- 允许配置设备级路线；
- 默认路线通常是上级路由；
- “本机路由”表示让设备流量经过本机复杂处理；
- “上级路由”表示让设备绕过本机处理；
- 页面需要醒目提示本机正在负责整个 LAN 的地址分配。

#### 无法可靠判断角色

- 不自动隐藏能力；
- 显示“当前网络角色无法确定”；
- 以 DHCP 分配权决定能否编辑设备路线；
- 在局域网设置中允许用户确认拓扑，并展示判断依据。

### 5.6 产品重要程度

“设备选择上网路线”的重要程度为高，使用频率为中，应位于设备详情核心区域；“维护路线目标”和“配置路由器角色”的重要程度同样高，但使用频率低，应位于局域网设置。

浮动网关是上网路线的一种高可靠目标，不应单独漂浮成与设备管理无关的技术插件。它的配置位于局域网设置，使用它的设备则在设备详情和列表摘要中清楚可见。

## 9. 信息披露原则

所有页面遵循以下五级披露：

1. **始终展示**：设备身份、在线状态和需要立即处理的异常；
2. **摘要展示**：地址、上网路线和使用限制的最终结果；非默认路线优先展示；
3. **编辑时展示**：具体设置字段、可选值和影响说明；
4. **配置后展示**：流量额度、定时计划和浮动网关状态；
5. **异常或高级展示**：原始证据、能力原因、审计和内部诊断。

补充原则：

- 无异常时不堆叠绿色技术状态；
- 无配置时使用简短的“未设置”，不展示大块空表单；
- 功能不可用时，只在用户尝试使用或确实影响当前结果时解释；
- 同一能力只存在一个正式编辑入口；
- 列表负责发现和选择，不承担完整配置；
- 移动端减少并列字段，不能把桌面表格直接压缩到窄屏；
- 不创建全局“简单模式 / 高级模式”，避免形成两套产品。

## 10. 状态表达原则

以下状态必须分开，不使用一个模糊的“状态”概括：

- **设备存在状态**：在线、离线、从未上线；
- **联网权限**：允许联网、暂停联网；
- **配置保存状态**：未保存、保存中、已保存、保存失败；
- **策略生效状态**：已生效、等待设备更新、无法验证、应用失败；
- **网络能力状态**：可用、未安装、已关闭、不可用、异常；
- **路线配置权限**：可配置、由其他 DHCP 服务器管理、角色无法确定；
- **需要处理状态**：地址冲突、路线异常、配额超限等具有明确行动的问题。

“需要处理”只收纳用户能够采取行动的异常，不能变成普通技术告警集合。

## 11. 核心交互原则

### 11.1 围绕设备，而不是围绕规则

固定地址、上网路线、限速和联网权限首先是某台设备的设置，不再拥有各自独立的产品首页。

### 11.2 一次编辑，一次预览，一次保存

同一台设备的相关设置统一进入编辑状态，底部提供：

```text
取消                         预览并保存
```

预览内容包括：

- 修改前后的值；
- 受影响的设备和网络能力；
- 是否需要终端重新获取地址；
- 是否可能短暂中断；
- 失败时恢复的内容。

### 11.3 规则显示结果和原因

用户首先看到最终结果：

> 暂停联网 · 来自“儿童设备”晚间计划

只有主动查看时才展开完整来源链。

### 11.4 支持从未上线的受管理设备

为保留现有离线规则管理能力，建议允许用户只凭 MAC 新建设备。该设备显示为“从未上线”，上线后自动补充观察信息。

这样地址、限速和路线始终属于设备，不再产生普通用户难以理解的“孤立规则”。

## 14. 待确认事项

### 14.1 一级和二级入口命名

推荐：

- 默认入口：“设备”；
- 批量与自动化：“分组与计划”；
- 低频基础能力：“局域网设置”。

候选替代：

- “分组与计划”可改为“自动管理”或“上网计划”；
- “局域网设置”可改为“网络设置”。

### 14.2 单设备例外的优先级

推荐：明确的单设备例外高于全局和设备分组；配额超限作为运行约束，可暂时阻断最终联网结果，并明确显示原因。

需要确认：单设备“允许联网”是否可以豁免设备组的晚间暂停计划。

### 14.3 现有配置的处理

推荐：不保留旧页面、旧接口和双写逻辑，但通过一次性迁移保留当前有效配置。迁移成功后只运行新模型。

需要确认：是否存在允许直接丢弃的旧配置类型。

### 14.4 专家信息的可达性

推荐：普通 UI 永不显示 DHCP tag 等实现细节；诊断导出可以包含脱敏后的内部映射，供支持人员排障。

需要确认：是否需要在 Web UI 中保留一个明确的“专家诊断”入口，还是只提供下载诊断包。

### 14.5 上网路线中的 DNS 行为

当前实现会把旁路由、浮动网关或指定 IP 同时下发为网关和 DNS。

**已确认：默认采用“DNS 跟随路线”。**

路线目标内部明确包含“网关地址”和“DNS 行为”；普通用户默认只看到一个路线选择。当前阶段所选旁路由、浮动网关或指定 IP 同时作为网关和 DNS 下发。数据模型保留 DNS 行为字段，为以后扩展“继续使用网络默认”或“指定 DNS”留出边界，但本阶段不在普通界面增加选择项。

### 14.6 旁路由无 DHCP 时的管理方式

**已确认：当前阶段只读展示并引导用户到主路由配置。**

界面提供本机网关 IP 复制；不自动开启第二个 DHCP，也不宣称可以跨路由写入。

未来可以规划 Quickstart 主、旁路由配对，使旁路由请求主路由为指定设备下发路线，但不属于当前阶段。

### 14.7 设备路线编辑权限

**已确认：始终以本机是否掌握 DHCP 分配权决定设备路线能否编辑。**

主路由、旁路由等拓扑角色用于优化默认值、说明文字和可选路线，不直接取代权限判断。角色无法可靠识别时，仍按 DHCP 分配权提供可编辑或只读界面。

## 15. 草稿确认标准

进入低保真交互设计前，需要确认：

- 用户需求的五个业务层级和一个安全基础层是否合理；
- “设备”为唯一默认核心入口是否成立；
- “分组与计划”和“局域网设置”的职责是否清楚；
- 所有现有能力是否已经被归入合适层级；
- 哪些信息始终显示、按需显示、异常显示和永不显示；
- 单设备例外、分组计划和配额约束的优先级；
- 设备备注名和网络主机名严格分离；
- 上网路线的 DNS 默认行为；
- 主路由、旁路由与 DHCP 分配权的角色感知规则；
- 旧产品入口删除与现有配置一次性迁移的原则。

确认本草稿后，再输出设备首页、设备详情、分组与计划、局域网设置四组低保真交互结构。
