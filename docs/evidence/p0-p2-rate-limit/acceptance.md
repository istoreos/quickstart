## 部署自动化收口

为避免文件级部署遗漏前端、缓存版本或回滚材料，本批次将部署契约收口为“后端 + 完整 Web 目录 + 模板版本”的原子候选安装：

- `deploy.sh` 在本地构建并校验产物，将候选交给远端安装器；远端先备份、再原子切换，并在健康检查或配置漂移时自动回滚。
- `verify.sh` 同时核对后端、前端入口、英文目录与模板缓存版本，不再只检查进程是否存活。
- 正式发布默认拒绝脏工作树，并为后端与 Web 产物生成可复核 `MANIFEST`。
- `quickstart-lan-main` 默认禁止部署；必须显式设置 `ALLOW_CRITICAL_GATEWAY_DEPLOY=1`。该保护已验证会在上传和重启前失败关闭。
- 新增登录态 UI SMOKE 包装器：通过临时 ubus 会话运行交互审计，并在退出时销毁会话。

新部署链路已在 B 旁路由实跑并通过完整校验；其完整回滚目录为 `/root/quickstart-backups/0.14.0-b60f6e53dd6a-20260926104828`。随后 A、B 均再次通过 UI SMOKE，各覆盖 `33` 个响应式状态且无阻断。主路由本轮没有再次部署或重启。

安装器本地测试覆盖成功安装与健康失败自动回滚；运维契约测试覆盖目标选择、关键网关保护、完整产物校验、UI 会话清理和正式发布脏树保护。

最终复验发现候选 SMOKE 曾错误沿用旧 OpenWrt 包源的固定产物哈希；这会在业务完全正常时产生 8 个假失败。现已将两类门禁拆清：正式发布模式继续严格核对 opkg 与发布哈希，候选模式则从当前本地候选产物计算后端、JS、CSS、图标和英文目录哈希，并要求 A/B 缓存版本非空且一致。修复后四机候选 SMOKE、双节点完整产物校验及双节点各 `33` 个 UI 状态再次全部通过。
