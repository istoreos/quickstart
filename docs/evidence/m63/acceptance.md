# M63 高级工具闭环验收

日期：2026-09-28  
拓扑：A `192.168.30.1` 只读；B `192.168.30.244` 执行登录态 API/UI 验收

## 安全探测

- 只在用户展开高级工具并点击后发送 HEAD 请求；不扫描地址，不读取响应正文，不跟随跳转，超时 2 秒，并发槽固定为 4。
- 实机以设备清单中 A 的稳定 `deviceId + 192.168.30.1` 探测 HTTP 80，返回 HTTP 200；公网 `8.8.8.8`、端口 22 和 `file` 协议均为 `validation_failed`。
- 目标必须是该设备当前拥有的私有或链路本地地址，允许端口只有 80、443、8080、8443。

## Webhook

- 默认关闭；读取接口只返回 `configured`，不回传 URL。带凭据 URL 与未知事件被拒绝且实机配置前后完全相同。
- 事件对外仅含稳定 HMAC 伪匿名设备标识，清空本地 reason，DNS reason 永不持久化；重启后同设备伪名稳定、不同设备不碰撞。
- 队列固定上限，拥塞时丢弃通知而不阻塞审计和核心策略；5 秒发送上下文、有限重试和禁止跳转均有自动测试。

## 策略备份与恢复

- 导出范围固定为全局/分组/单设备使用规则与流量额度，不包含地址、路线、限速和防火墙规则。
- 实机完成：导出 → 同值 dry-run/幂等 apply → 不确认拒绝 → 不兼容版本拒绝 → 临时空分组 apply → 再导出确认 → 原包重新 plan/apply → 规范化内容逐字节一致；无临时分组残留。
- Apply 必须同时匹配 dry-run checksum 与当前分组 version；流量额度保存失败时分组自动恢复。请求体上限 4 MiB 且只接受单个 JSON 值。

## 正式 UI 与运行安全

- Playwright 在桌面与手机登录态实际点击 HTTP 探测、下载策略包、重新选择文件并出现“预检通过”；没有点击最终确认，截图与报告位于 `docs/evidence/m63/ui/`。
- 高级工具默认折叠，通知默认关闭，恢复按钮只在预检后出现；普通设备列表不增加任何高级入口噪音。
- `make test-lan-advanced-tools` 本地与设备模式均通过。A/B 的 network、dhcp、firewall、dnsmasq 和 quickstart 进程指纹前后不变。

结论：`LAN-008`、`OPS-006`、`OPS-007`、`OPS-008` 五层证据闭环。
