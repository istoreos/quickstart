# 局域网设备管理人工验收清单

> 候选：Quickstart `0.14.0` / M64 业务验收候选  
> 页面：`http://192.168.30.244/cgi-bin/luci/admin/quickstart/devicemanagement`  
> 安全边界：所有保存和应用只在旁路由 B 或专用测试设备执行；主路由 A `192.168.30.1` 只读。

这份清单从用户任务验证业务是否完整。底层 Provider、UCI、DHCP tag、option 3/6 和 eBPF 不应成为普通操作前提。人工确认不替代后续独立的 24 小时稳定性观察。

## 一、先确认页面结构

1. 打开页面，应只有“设备”“分组与计划”“局域网设置”三个一级区域。
2. 列表默认能看清设备名称、品牌/类型、在线状态、地址、连接方式、实时流量和规则摘要。
3. 分别在桌面和手机宽度打开页面，不应出现页面级横向滚动、遮挡或只能靠猜测理解的技术名词。
4. 搜索并组合使用连接方式、品牌、策略筛选；已打开的设备即使被筛选隐藏，详情和未保存输入也不能丢失。

通过标准：三层信息架构清楚；列表简洁；详情上下文稳定；空、加载、失败和数据预热状态可区分。

## 二、设备资料

在一台测试设备的“设备资料”中完成：

1. 将设备备注改为中文，例如“客厅测试电脑”，保存并刷新页面。
2. 检查品牌、设备类型、原始厂商和识别依据互不冒充；人工修改品牌或类型后可以恢复自动推荐。
3. 选择一个手动图标，刷新后仍保持；再恢复自动图标，应按品牌文字与设备类型呈现，未知设备回退为通用电脑形态。
4. 重启 B 的 Quickstart 后再次确认资料仍存在。

通过标准：中文只进入设备备注，不进入 DHCP；资料保存不改变地址、路线、分组或使用限制。

## 三、网络与上网

选择专用测试设备，不要使用当前管理终端：

1. 启用地址预留，填写合法 IPv4；在 DHCP 主机名中先输入中文，保存必须被阻止且 dnsmasq 不受影响。
2. 改为 ASCII 单标签主机名，例如 `living-room-pc`，选择“默认路线”、旁路由或浮动网关，进入预览。
3. 预览应明确显示地址、网关与“DNS 跟随路线”，确认后显示“配置已应用”与终端实际效果的区别。
4. 让测试终端续租或重新联网，检查 Observed Effect；随后恢复原配置。

通过标准：非法输入零写入；路线与 DNS 成对；等待续租不显示成已生效；恢复后无孤立 DHCP 规则。

## 四、使用管理

1. 设置上传/下载最高速度，先看预览再应用；用测试流量确认 IPv4 与 IPv6 都按同一 MAC 身份受限。
2. 删除限速，速度应恢复；联网权限不应被同时改变。
3. 暂停测试设备联网，再恢复；该操作不依赖限速组件，也不能误删仍需保留的限速规则。
4. 设置跨午夜时段和一个短周期测试额度，确认来源说明为“全局 → 分组 → 设备例外”，设备例外优先。

通过标准：联网权限、最高速度、时段和额度是四个可解释的结果；缺少某个可选组件只锁住对应能力。

## 五、分组与批量计划

1. 新建测试分组并加入至少两台测试设备，设置共同路线或使用规则。
2. 给其中一台增加设备例外，预览必须提示例外数量和最终优先级。
3. 保存后检查两台设备的“规则来源”；删除测试分组或恢复原设置。

通过标准：分组不是 DHCP 标签；一次批量任务对每项底层服务最多重载一次；删除后不残留成员和计划。

## 六、局域网设置与规则台账

1. “网络服务”应集中展示 DHCP、地址池、租期、默认路线和限速服务状态；高风险修改必须先预览影响设备。
2. “上网路线”能创建、编辑、引用和删除自定义网关；使用中的路线必须选择替代项才能删除。
3. 浮动网关已配置时默认展示虚拟 IP、节点角色、当前持有者、健康与最近切换信息，而不是重复初始化向导。
4. “规则台账”能统一筛选地址、路线、联网权限、限速和额度规则，并能识别离线、孤立或不可达规则。

通过标准：普通界面只使用用户概念；没有裸 DHCP tag、option 或 Provider；危险操作可预览、可取消、可恢复。

## 七、依赖降级、恢复与高级工具

1. 可选能力显示“可用 / 未启用 / 未安装 / 不支持 / 错误”之一；未知状态必须失败关闭。
2. 组件不可用时，设备清单、设备资料和无关能力仍正常；安装或恢复后返回原任务，草稿仍在但不会自动应用。
3. 高级工具默认折叠；设备管理入口探测只允许当前局域网地址和批准端口，不扫描、不跟随跳转。
4. 导出策略包，再导入做 dry-run；只有版本、校验和当前状态一致时才出现最终恢复确认。
5. 制造一次可恢复失败，界面应区分“原设置已恢复，可以重试”和“需要人工恢复”。

通过标准：局部故障不拖垮整页；所有写入任务都有 plan → validate → apply → verify → rollback 结果。
