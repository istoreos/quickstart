# 多 LAN 实施里程碑与验收计划

状态：M01–M09 阶段验收已通过；M10 第 5 轮在完整应用预热期间发现计划断网未按预期阻断 IPv4，已停止，尚不具备上线条件。最新结果见 [执行记录](../evidence/multi-lan/execution.json) 与 M10/progress.md。

依据：[已认可的实施口径](../../product/multi-lan-design.md#实施前收敛兼容优先按需展示)。该文档前部的收敛要求优先于后部探索性原型。

目标：单 LAN 用户保持原有使用方式与数据，多 LAN 用户在现有设备管理页面选择网络；设备、配置、执行、后台任务和恢复均具有一致的网络作用域。

## 一、统一的完成规则

每个里程碑都必须交付代码、适当层次的自动化测试、可复现的验收记录以及必要的契约/文档更新。验收记录至少包含两仓库对应版本、配置场景、命令、预期、实测、测试环境与未完成项，不包含凭证。

- 状态使用 `not_started / in_progress / passed / failed / blocked`；缺环境或未执行不能记为 passed。暂不具备实机条件的里程碑保持未通过，并保留已经完成的本地证据。
- 测试分为本地业务测试、真实页面浏览器检查、设备配置/进程检查、真实数据包验证四层。只有相关层次全部通过才满足该里程碑，不能用一个层次替代另一个。
- “操作 lan1 不影响 lan2”必须检查 lan2 的配置语义、目标策略和受控行为，不只检查请求参数。自然变化的运行计数单独比较，不要求无业务意义的整文件字节一致。
- 每个网络写入必须有成功、重复请求、配置冲突、目标失效、失败恢复的验证；有共享资源的还要验证并发修改。
- M01 固定功能支持矩阵。普通独立 LAN 的设备发现、DHCP/地址保留/路线、NetPolicy 限速/配额、网络内分组和计划是实现目标，不能通过统一禁用来宣称完成。特殊拓扑或旧 provider 确实无法隔离时，须在矩阵逐项说明范围、原因和预期降级行为。
- 不得在后续实现中自行把失败的必需场景改成“不支持”。单 LAN 的现有功能必须保留；未支持的复杂组合不能退回默认 LAN 执行。
- 默认 LAN 保留旧设备 ID、存储位置和 NetPolicy main 配置；新增 LAN 隔离持久数据、缓存与后台执行状态。
- 每阶段评审代码可读性：一套业务实现、集中网络解析、显式作用域依赖。避免全局 currentLAN、复制页面/ServiceBackend、通用工作区框架和仅为未来功能设计的接口。

## 二、公共场景库

场景可组合，后续里程碑按用例编号引用。同一组输入用于后端、前端 fixtures 和实机准备，避免三套不同含义的数据。

| 编号 | 场景 | 必须观察到的行为 |
| --- | --- | --- |
| T01 | 现有 `lan → br-lan`，带已有资料、分组、地址保留、路线、限速、配额和历史 | 原数据可读、原操作可用、无需重新配置或启用服务 |
| T02 | 唯一逻辑网络 `office → br-office` | 自动进入唯一网络，单 LAN 页面无额外选择步骤 |
| T03 | `lan + lan1 + lan2`，独立设备、不同网段 | 可汇总和切换，目标与能力独立 |
| T04 | 只有 `lan1 + lan2`，没有默认 `lan` | 新版正常工作；旧版无网络写入不猜测目标 |
| T05 | `lan1/lan2` 为同一网桥的物理端口 | 只识别一个 LAN，连接端口不冒充逻辑网络 |
| T06 | VLAN 子接口、同桥逻辑别名、父桥/子接口组合 | 正确解析或明确限制；不重复挂载、计数和执行 |
| T07 | DHCP section 与接口不同名；单/多 dnsmasq、自定义 leasefile | 按实际绑定读取与修改，无法确定的绑定拒绝写入 |
| T08 | LAN 本机 DHCP、外部 DHCP、服务异常和多 DHCP 证据 | 各网络独立判断地址分配权；无副作用的明确降级 |
| T09 | 多 LAN 分属不同 zone，或共用同一 zone | 网段名和 zone 不混用；规则不能误伤同 zone 的其他 LAN |
| T10 | 两个独立 LAN 使用相同 MAC/DUID；设备从一个 LAN 移动到另一个 | 观察、资料、历史和策略不串网；迁移不自动复制原网络策略 |
| T11 | 双栈、仅 IPv6、link-local、DUID/IAID 无可靠 MAC | 链路维度保留，地址不跨网合并；不支持的执行身份准确提示 |
| T12 | 前缀重叠、租约来源歧义、无法归属的手动/离线记录 | 不猜测；保留未知或受限状态。普通首版不宣称支持 VRF/netns 重叠地址管理 |
| T13 | 网络停用/删除/改绑/重建，接口消失重现，进程重启 | 旧目标和旧计划失效，恢复前重新确认作用域与执行实例 |
| T14 | 单引擎异常、端口/目录/设备冲突、与 Bandix/eQoS 争用 | 错误限定在对应能力或真实共享依赖；不抢占和不错误宣称有效 |

## 三、里程碑

### M01：固定契约、支持矩阵和单 LAN 基线

依赖：无。仓库：Quickstart、NetPolicy。

交付：接口与数据兼容约定、所有业务入口清单、T01–T14 测试输入、旧数据样例、数值资源预算与支持矩阵。明确“可管理逻辑网络”“当前网络”“总览”“未知归属”四个术语。

可测试目标：

1. 记录现有后端、前端和 NetPolicy 测试的实际结果；已有失败要复现并说明，不把未运行当成功。
2. T01 完整记录设备资料、地址保留、上网路线、使用限制、分组计划、配额、功能组件、规则台账和恢复流程的基线；包含重启后的读回结果。
3. 固定旧接口缺少网络参数的语义、新字段的兼容规则、新前端如何识别旧后端，以及计划/幂等/缓存的网络身份规则。
4. 列出所有 GET、plan、apply、后台任务、导入导出和旧入口，逐项指定后续负责的里程碑。特别包括浮动网关、旧 eQoS/Bandix provider、网络探测、webhook 和策略包。
5. 为目标设备填写可判定的 CPU、RSS、BPF map 内存、API/采样延迟和持久化写入预算；记录设备型号、内核、数据规模和测量方法。预算不能在 M10 看到结果后再放宽。

完成判据：基线与矩阵有实际结果；所有必需行为有用例编号和负责阶段；资源预算有数值。此阶段不开放新业务能力。

### M02：统一 LAN 解析与请求作用域

依赖：M01。仓库：Quickstart。

主要位置：`backend/service/network_interface_inventory_*`、拟新增 LAN 作用域模块、`backend/models/`、`backend/modules/lancontrol/routes.go`、`backend/yamls/lanctrl.yaml`。

可测试目标：

1. T01–T06、T09 中正确区分逻辑网络、网桥、物理端口、VLAN 和 zone；不依赖 `lan*` 前缀，不漏掉唯一自定义 LAN。
2. T07 解析实际 DHCP section/instance；发现不等于开启 DHCP、创建防火墙规则或启动策略实例。读取前后配置无业务变更。
3. 所有相关路由统一解析作用域。总览只能读；显式无效/不存在网络和参数冲突返回明确错误，不进入默认 LAN 的写入路径。
4. 旧调用缺少网络参数时维持默认 lan 行为；T04 的旧写入失败且配置不变。查询失败不能被当作“只有一个 LAN”。
5. 并发发起两个 LAN 的请求，验证依赖、上下文和结果不互相覆盖；禁用服务级可变 currentLAN。
6. T13 变化后重新解析绑定并使旧解析结果不可写，不引入独立网络 UUID 管理平台。

完成判据：场景与路由契约测试通过；有跨 LAN 并发业务验证；相关读请求没有配置副作用。

### M03：设备发现、身份、资料与存储隔离

依赖：M02。仓库：Quickstart。

主要位置：`network_device_list_usecase.go`、`device_inventory_v2*.go`、`device_profile*.go`、`device_classification*.go` 及模型和存储适配。

可测试目标：

1. T03/T04 的 ARP/NDP、DHCPv4/v6、host hints 和 Wi-Fi 证据正确归属；遍历实际 leasefile，不只读取默认文件。
2. T10 相同 MAC/DUID 在两个 LAN 形成两个独立接入目标；T11 的 link-local 不跨链路合并。去重发生在正确作用域内。
3. 修改 lan1 设备的别名、分类、图标或手动记录，lan2 同 MAC 的资料保持原值；重新启动后仍正确。
4. T12 的歧义记录保留“归属未确认”，不能隐式归到 lan；旧资料只在归属可证明时映射，不能复制给所有网络。
5. T01 原设备 ID 与数据位置保留；新增 LAN 的历史、资料和缓存隔离。缓存命中、失效、容量限制和历史淘汰均不跨网络泄漏。
6. T10 设备迁移后正确区分当前与历史网络证据，不自动迁移策略；T13 网络删除后历史不误成为新网络的在线事实。

完成判据：后端业务测试和至少一组双 LAN 采集验证通过；真实重启读回正确；资料与历史负向隔离测试通过。

### M04：共享配置事务、计划校验与恢复

依赖：M02，设备目标测试依赖 M03。仓库：Quickstart。

主要位置：`task_transaction*.go`、共享 UCI 写入/恢复适配、各 plan/apply 契约及审计记录。

可测试目标：

1. plan 固定网络、目标、配置/绑定版本和适用的执行实例身份。把 lan1 的计划用于 lan2、把设备与网络交叉组合、篡改目标，均拒绝且无业务写入。
2. T13 网络删除、改绑或重建后，旧计划不可继续执行；引擎相关计划在实例重启/身份变化后也要重新核对。
3. 不同 LAN 同时修改 `/etc/config/dhcp` 或同一服务，串行保护共享资源；两次合法修改最终均保留，不只是各自返回成功。
4. 注入“快照后、写入后、reload、verify、restore”失败，验证成功恢复或明确 recovery_required。任何阶段不能显示虚假的成功。
5. 故障回滚不能覆盖另一 LAN 已成功提交的配置；覆盖所有参与写入的正式/旧入口，锁的有效范围与实际进程模型一致。
6. 幂等键在不同 LAN、不同任务下不碰撞；重复请求不重复执行。事务/审计能定位网络和最终状态。

完成判据：并发与故障注入测试通过，并在隔离设备环境完成一次失败恢复演练。未通过前不开启新增 LAN 的系统写入。

### M05：DHCP、地址保留、路线与浮动网关适配

依赖：M03、M04。仓库：Quickstart；实际系统组件按 M01 矩阵验证。

主要位置：`lan_dhcp_*`、`lan_static_assignment_write_*`、`gateway_policy*`、`device_network_policy*`、`floating_gateway*`、`lan_global_config_*`。

可测试目标：

1. T03/T07 修改 lan1 的启停、地址池、租约时间和默认网关/DNS，实际客户端获得预期租约；lan/lan2 的配置与租约选项保持各自语义。
2. 地址保留校验使用当前网络的前缀、路由器地址、网关、浮动地址和保留地址；非法地址被拒绝。相同 MAC 的 host/tag 编译经过真实 dnsmasq 配置预检，不凭空添加不存在的隔离字段。
3. 路线增删改、设备绑定、替代路线和引用检查均限定网络；删除 lan1 路线不能修改 lan2 的引用。
4. T08 每个 LAN 单独判断 DHCP 权限与健康；外部 DHCP 或歧义绑定无法写入对应网络设置，不自动开启服务。
5. 预览准确列出修改网络与共用服务影响；共享 dnsmasq reload 时不能承诺其他 LAN 的运行完全无影响。失败恢复符合 M04。
6. 浮动网关配置、状态、探测/演练和能力作用域逐项验证。T01 原功能保持；其他 LAN 仅在底层能可靠隔离时开放，否则按 M01 的明确限制展示并拒绝误操作。

完成判据：业务测试、UCI/dnsmasq 预检、真实客户端租约与网关/DNS 检查、跨 LAN 不受误改和失败恢复全部通过。

### M06：NetPolicy 多实例与服务端实例选择

依赖：M02、M04；可在 M05 完成前单独开发，但不提前宣称集成完成。仓库：NetPolicy、Quickstart。

主要位置：NetPolicy 的 `packaging/quickstart-netpolicy.{config,init}`、`bandix/src/{command,web,engine_guard}.rs`、`policy/`、`storage/`；Quickstart 的 native provider 与实例配置解析。

可测试目标：

1. 旧 main 配置不变即可启动，使用原端口与目录；新实例各有独立设备、控制端点、data_dir、revision、eBPF 对象及文件。
2. T10 两实例接受相同 MAC 的不同策略并独立读回；跨实例重用计划被拒绝或由 Quickstart 在调用前拦截。owner 的目标集合替换不删除该实例其他设备或其他 owner 的策略。
3. Quickstart 只根据已验证的服务端绑定选择实例；health 的实际接口/实例不匹配时拒绝写入。浏览器不能指定任意 baseURL 或端口。
4. 重复端口、目录、设备配置和 T14 引擎争用有明确错误；不停止无关服务，不抢占接口。控制端点只按约定暴露于本机。
5. T06 不在重叠父桥/子接口重复挂载；T13 单实例停止、崩溃、重启、接口重建、配置 reload 和整机重启后，健康网络的状态与策略仍正确。
6. 清理仅释放自身持有的 TC link/lease。新增实例启停不删除其他实例的挂载点或状态文件；单实例 reload 不无条件重启全部健康实例。
7. 旧 Quickstart + 新引擎、新 Quickstart + 旧引擎、新新组合按 M01 矩阵通过。旧单实例引擎不能被宣称具备多实例能力。

完成判据：Rust/打包启动测试、Quickstart provider 集成测试，以及实机双实例启停、重启与故障隔离通过；保留单实例内 MAC key，无无必要的内核 ABI 升级。

### M07：限速、访问控制、流量历史与配额

依赖：M03–M06。仓库：Quickstart、NetPolicy。

主要位置：`device_policy*`、`device_restriction_store.go`、`rate_limit*`、`lan_stats*`、`device_traffic.go`、`traffic_insights*` 及 NetPolicy 对应流量/策略模块。

可测试目标：

1. T10 同 MAC 在两个 LAN 设置不同上下行限速，通过实际 IPv4/IPv6 流量分别验证，修改一边不改变另一边。限速允许误差、测量窗口和测试流量在 M01 固定。
2. T09 共用 zone 时，访问控制仍精确作用于目标设备及其网络；取消限制恢复原行为，不改其他 LAN 策略。
3. eQoS/Bandix 等旧 provider 保持原单 LAN 行为；无法按网络隔离的范围明确不可用，不能调用默认实例代为执行。
4. 流量取样、地址归属、历史和配额按网络隔离；实例重启、计数器归零/回绕、地址变化不产生负数、巨大增量或无故额度刷新。重启后已耗尽额度不能意外恢复可用。
5. 达到配额后的阻断/限速、周期更新、取消额度和失败恢复，均通过真实流量验证；不误阻断其他 LAN，也不覆盖设备原有的访问限制。
6. 跨 LAN 内部访问不误作为公网用量重复累计；总览不把双侧观察到的内部流量简单相加。区分未知、过期、零流量和服务异常。
7. 路由/旁路/桥接、软/硬 offload 路径按 M01 矩阵验证；流量绕过挂载点时不能报告“已验证生效”。单 LAN 既有口径与行为回归通过。

完成判据：业务集成测试、持久化/重启测试、双 LAN 双栈吞吐与配额实测通过。只有配置已保存而没有数据包验证不能判定生效。

### M08：分组计划、规则台账与辅助业务完整覆盖

依赖：M05、M07。仓库：Quickstart。

主要位置：`device_groups*`、`network_rules*`、`network_audit.go`、`advanced_network*`、`management_probe*`、`policy_bundle*`、`capability_action*`、接管与迁移模块。

可测试目标：

1. 分组成员、默认策略、单设备例外、路线引用和最终优先级按 LAN 计算；伪造跨网络成员/引用会被拒绝。原“全局策略”对旧默认 LAN 的效果保持。
2. 定时计划在用户离开页面、切换 LAN、重新登录和重启后仍在正确网络执行；不能依赖浏览器当前选择。单 LAN 计划故障不污染其他 LAN 的运行状态。
3. 批量应用返回真实的逐目标结果，失败恢复不覆盖成功网络；批处理不引入逐设备无界 reload。
4. 规则台账、搜索、接管/迁移、删除及审计记录显示真实网络；非默认 LAN 的规则不能被误当默认 LAN 接管。
5. 诊断/管理探测使用正确设备、源地址和网络；导出包含作用域，导入有明确目标和预览，跨网络误导入被拒绝或要求显式映射后重计划。
6. webhook 的去重/事件网络标识、事件节流和故障处理正确；测试使用本地可控接收端，不发送真实外部通知。
7. 功能组件的安装状态与当前网络可用状态分开；安装/启停操作准确展示真实共享影响范围，不把组件安装误报成每个网络已接入。

完成判据：后台调度、优先级、导入恢复、诊断和事件测试通过，并在双 LAN 环境完成一次离开页面后的真实计划执行验证。M01 入口清单无未分配业务。

### M09：正式页面与单 LAN 易用性

依赖：M02/M03 可开始 UI 骨架；完成依赖 M05–M08。仓库：Quickstart。

主要位置：`web/src/pages/device/`、统一 LAN 上下文与请求入口、`web/src/request/`、首页/旧入口、`web/src/design/*Fixtures*`。

可测试目标：

1. T01/T02 无多余网络选择、总览卡片或配置步骤，复用三个页签。普通用户不需要填写网桥、zone、端口或 revision。
2. T03/T04 显示一个清晰的网络选择入口；总览用于找设备，选定网络编辑 DHCP/分组/路线。未知归属作为状态/筛选，不新增管理台。
3. 总览设备详情、资料、限速等操作携带行目标的网络；同 MAC 两行的 row key、选中项、抽屉、趋势和草稿互不混用。
4. 在设备抽屉、未保存表单和变更预览中切换网络，正确关闭/处理草稿并清理旧目标。模拟慢响应倒序返回和失败重试，旧响应不能覆盖新网络。
5. URL、刷新、前进/后退、首页摘要和旧入口跳转保持网络语义。无效/已删除网络提示失效，不静默切到其他可写网络。
6. 网络清单接口明确不支持时可回退旧单 LAN 页面；401/403、超时和服务错误分别处理，不回退成“只有默认 LAN”。升级/版本能力按 M01 契约验证。
7. 桌面、390px 移动端、键盘操作和现有主题可用；不引入页面横向溢出。状态文案讲业务范围与下一步，不泄漏必须由用户理解的实现概念。
8. `scripts/ui-design.sh` 在真实 `/devicemanagement` 页面展示单/多 LAN fixtures；此外通过正式前端构建连接测试后端完成业务验证，独立原型截图不能代替。

完成判据：前端业务测试、真实页面浏览器检查、单 LAN 回归截图与多 LAN 后端联调通过；原先用户使用的页面已具备该能力。

### M10：升级兼容、容量与发布验收

依赖：M01–M09 全部通过。仓库：Quickstart、NetPolicy。

可测试目标：

1. 从 T01 的旧配置升级：已有资料/地址/路线/分组/计划/限速/配额/历史完整读回并继续生效，用户不需要重新设置。
2. 迁移可重复执行且有标记；失败注入后可恢复，旧数据不被删除或复制到所有 LAN。对无法可靠归属的数据给出真实状态。
3. 验证旧前端/新后端、新前端/旧后端，以及旧/新 NetPolicy 的兼容组合。各组合开放的能力与 M01 矩阵一致。
4. 部署候选构建并记录两仓库版本和制品身份，按 T01–T14 完成最终支持矩阵；执行整机重启、网络热插拔、引擎异常和配置恢复演练。
5. 在目标设备测量 1/2/4 个 LAN（受测机不支持 4 个时不能据此宣称支持 4 个）的 CPU、RSS、BPF 内存、API/采样延迟和写入量，全部满足 M01 固定预算。对外支持上限不能超过通过验证的组合。
6. 至少 24 小时稳定性测试，包含持续流量、周期采样和已启用的后台计划；错误目标写入、错误阻断、计数归属泄漏为零；无无界内存/文件增长。不能以短时原型测试代替。
7. 回退演练同时处理二进制、配置和数据格式；旧版本不能误读新格式后覆盖多 LAN 数据。无法安全降级的组合必须明确阻止写入或采用已验证备份恢复路径。
8. 产品与代码收敛评审通过：单 LAN 默认体验保持，一套真实业务页面，一处网络解析，无复制的业务后端/存储实现；旧固定 LAN 使用点逐一记录保留理由或完成替换，新手向导的原语义不被全局替换破坏。

完成判据：最终覆盖矩阵无必需项未测/失败，资源与稳定性达标，升级/恢复/回退证据齐全。此时才可宣称所列支持范围内完整支持多 LAN。

## 五、检查入口与证据

现有检查可以复用，但必须按上述场景扩展，不能因为原有单 LAN 测试通过就认为多 LAN 通过。

Quickstart 已有本地入口（从仓库根目录执行；下列仅列出命令，本计划阶段未执行）：

```sh
rtk proxy /var/cache/build-cache/run.sh -- make test
rtk proxy /var/cache/build-cache/run.sh -- node --test web/test/*.test.mjs
rtk proxy /var/cache/build-cache/run.sh -- npm --prefix web run tsc
```

NetPolicy 已有 `make test`，在其项目目录通过相同 SSD wrapper 执行；涉及完整 eBPF 构建时保留项目工具链和目标约束，实际输出目录必须核验。

现有设备验证入口包括 Quickstart 的 `scripts/ops/lan-device-{identity-address,capability-context,route,transaction-migration,rate-limit,groups-schedule,traffic-quota,ipv6,advanced-tools,topology-soak}-smoke.sh` 相关脚本，以及 NetPolicy 的 `scripts/smoke/{topology-smoke,ipv6-topology-smoke,resource-check}.sh`。其中 soak 的实际文件名是 `lan-device-topology-soak.sh`，不能根据括号示意直接拼出不存在的文件。

建议在实施中增加一个多 LAN 验收汇总入口，接收上述场景结果并按需求矩阵判定；这是拟新增工具，当前不存在。缺场景、缺版本、用模拟数据冒充实机、必需项 skipped 或恢复失败均不得生成整体 passed。

证据建议保存在 `docs/archive/evidence/multi-lan/Mxx/`，包含结果 JSON、最小可复现配置、相关日志/截图和恢复检查。结果表分别记录本地、浏览器、配置和数据包验证状态，未涉及的层次说明原因，涉及但未运行的层次不得通过。
