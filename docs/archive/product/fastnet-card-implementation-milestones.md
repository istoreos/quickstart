# FastNet 外部卡片实施里程碑与验收计划

状态：FN01–FN12 已通过。最终审计覆盖 76 项验收、30 项需求、12 类主题和 10 项预算；两架构实验设备已恢复基线。实际结果以各阶段证据为准。

计划包含 12 个阶段、76 项阶段验收目标，并用 30 项需求覆盖矩阵、12 类主题场景和 10 项资源预算追踪完整性。主题场景中的组合与子场景均需分别留证。

目标：Quickstart 内置可安装模块的最少元数据；已安装插件注册外部卡片；FastNet 自行维护卡片内容并由 luci-app-fastnet controller 提供同源 API；卡片沿用首页布局、共享运行时、基础 CSS 和右上角浅色、深色、跟随系统三态主题。

按仓库[文档约定](../../README.md)，阶段计划保存在本目录。卡片外观见[产品说明](../../product/fastnet-card-design.md)，本计划的实施口径优先于历史模拟原型中的安装与静态加载方式。

## 仓库边界和基线

| 别名 | 仓库与范围 | 编写计划时的提交 |
| --- | --- | --- |
| Q | 当前 Quickstart 仓库；首页、主题、模块发现、外部运行时与布局持久化 | 81018a2 |
| F | 用户指定的 linkease-github/fastnet；独立卡片构建与 Go 测速任务 | 190a412 |
| P | 用户指定的 istoreos-app-hub/apps/fastnet；controller、LuCI 静态资源、注册和包配方 | b11d3be |

上述版本是后续 FN01 的起点，实施和验收时记录实际使用版本。不得把不同提交、构建产物或设备环境的记录拼成一次通过。

已确认的技术边界：

- FastNet 默认未安装。可安装名称、图标、介绍与 app-meta-fastnet 安装要求内置 Q，不修改 iStore 自身实现或协议。
- 卡片注册由 luci-app-fastnet 包负责；没有 controller 的核心程序不能被当作完整卡片。资源随插件安装，不内置完整 FastNet 前端到 Q。
- 卡片业务仅覆盖默认外网出口的最近下载、上传、测速时间、NAT 与 IPv6，以及测速进度、停止、重试、详情和完整 Web 入口。
- Q 负责安装提示、CardShell、公共样式、布局、主题、加载错误态；F 负责业务组件和实际检测；P 提供公开的 summary/run/task/cancel 同源接口。
- 三态主题继续使用现有 ThemeSnapshot：preference=system/light/dark，effective=light/dark；system 对应 LuCI body[theme=normal]，实际颜色由 data-quickstart-theme 表达。
- 主题偏好只保存在浏览器；插件不另存主题，不增加自己的系统主题监听，不改 body 或 FastNet UCI。
- 卡片移动、隐藏、换形态或切主题不创建新任务；页面离开不终止后台任务。服务/设备重启使原任务 interrupted，不自动重测。
- 不包含 LAN 卡片、完整测速工作台、多 WAN 绑定、插件市场或跨框架桌面运行时。以后增加出口必须先确认引擎能力，并扩展结果上下文。
- 当前设计预览的静态导入和运行时修改全局模块清单只属于模拟实现，不能直接作为生产外部模块机制。

## 完成规则和测试证据

每个里程碑都交付对应代码、适当层次的自动化测试、可单独运行的测试入口和验收记录。状态使用 not_started、in_progress、passed、failed、blocked；case 使用 passed、failed、not_run、blocked。

只有依赖阶段已通过、所有必需 case 实际执行通过、完成判据满足，阶段才能为 passed。缺设备、未执行、仅代码审查或仅模拟通过都不能替代要求的实机验证。修复改变了产物后，应重跑受影响 case，不能沿用修复前的通过记录。

验收分为以下层次，各阶段按可测试目标要求执行：

| 层次 | 用途 | 不能替代的内容 |
| --- | --- | --- |
| 契约与确定性业务测试 | 模块、配置、状态机、错误、幂等和存储行为 | 实际 HTTP 服务、包安装或真实测速 |
| 本地浏览器和独立构建 | 真正 ESM 加载、共享运行时、主题、布局、请求与清理 | LuCI 认证、包管理和真实网络结果 |
| 实际 controller 与包验证 | 登录态、写保护、依赖、资源、缓存、安装升级卸载 | 真实引擎与服务重启行为 |
| 实机端到端与资源采样 | 同一 runId 结果、后台恢复、设备开销、架构与升级回退 | 其他未测架构或版本组合 |

测试证据归档到 `docs/archive/evidence/fastnet-card/<run-id>/FNxx/`。每份报告至少包含：

```json
{
  "milestone": "FN02",
  "status": "in_progress",
  "revisions": {"quickstart": "<sha>", "fastnet": "<sha>", "packages": "<sha>"},
  "artifacts": {"sdk": "<version>", "card": "<hash>", "packages": ["<name-and-sha256>"]},
  "environment": {"device": "<test-label>", "arch": "<arch>", "firmware": "<version>", "browser": "<version>"},
  "cases": [
    {"id": "FN02-T01", "status": "not_run", "command": "<reproducible-command>", "expected": "<expected>", "actual": "<actual>", "evidence": []}
  ],
  "budgetResults": [],
  "unresolved": []
}
```

报告不得包含登录凭证、API token 或真实私人设备清单。截图、HTTP 记录、结果、资源采样和包摘要需要回到持久目录，不能只留在 SSD 临时构建缓存。

| TH02 | 显式浅色，初始系统深色 | 首次挂载即浅色，不被媒体查询覆盖 |

## 资源预算

以下是首版验收初始门槛，不是当前实测结果。FN01 在两种架构的实际测试环境中记录基线、冻结测量方法和最终数值；若硬件确实不适用，必须在依赖阶段实现开始前记录具体调整、原因与适用范围。不能在 FN10 看到超标后通过放宽门槛把失败变为通过。

KiB=1024 字节。浏览器体积、设备基础 FastNet 服务开销、卡片增量开销分别报告。预压缩与长缓存以设备实际响应为准，不假设 uhttpd 已支持某项配置。

| 编号 | 门槛 | 计量口径 |
| --- | --- | --- |
| B01 | 新增宿主通用加载器与 SDK 的首屏 JS/CSS gzip 增量 ≤20 KiB；FastNet 专用 JS ≤32 KiB 原始、≤10 KiB gzip | 与 FN01 同浏览器/构建配置的 Q 基线比较；不得把第二份 Vue 计作已共享资源排除 |
| B02 | FastNet 专用 CSS 优先 0，最多 ≤8 KiB 原始、≤2 KiB gzip；卡片专用字体、位图和图表依赖为 0 | 独立产物和依赖图审计；不通过把卡片样式搬进一个大宿主包隐藏增量 |
| B03 | 摘要 GET p95 ≤500 ms；run 提交 p95 ≤1 s | 每个平台有线本地访问，预热 5 次后 30 次采样；run 延迟不包含真实测速耗时，模拟和实机分开报告 |
| B04 | summary JSON ≤8 KiB，task JSON ≤4 KiB，已安装 manifest 聚合响应 ≤64 KiB | 记录序列化后未压缩字节，列表/日志有界，不携带完整历史和诊断日志 |
| B05 | 未安装或未添加：FastNet JS/API 请求均为 0；可见闲置卡片首次读取后连续 60 s 周期请求为 0 | 排除显式刷新、重新可见、安装完成及用户动作；首次只读不执行探测，原首页已有采样单独统计 |
| B06 | 运行期每页面只保留 1 条任务查询，间隔至少 2 s；请求截止 ≤8 s；连续 3 次查询失败后暂停自动查询 | 下一次请求在前一次完成后安排；隐藏/卸载取消查询；恢复可见先读同一 taskId，不重新 POST run |
| B07 | 每个成功 entry 版本在同一页面只导入一次；主题/重排导致额外模块下载和重新测速次数为 0 | 浏览器 trace、加载器计数与真实 HTTP 缓存记录；禁止 Date.now 生成新 entry URL |
| B08 | 预热同一模块后挂载/卸载 50 次，卡片 DOM/定时器/观察器/订阅/pending 请求残留为 0；GC 后堆增量 ≤2 MiB | 固定浏览器和 fixture，排除宿主本来保留的全局主题监听与 ESM 模块缓存；不能用未预热堆作比较 |
| B09 | 同版 FastNet 服务运行时，显示闲置卡片的设备 CPU 均值增量 ≤1 个百分点，RSS 增量 ≤8 MiB，新增常驻进程为 0 | 每个平台预热 30 s、比较 3 组各 60 s 配对采样；FastNet 基础服务本身资源也需单独报告 |
| B10 | 设备同时最多 1 个占用测速资源的任务；最多保留 32 条任务摘要；每任务日志 ≤64 KiB；任务截止 ≤120 s，停止/截止后 ≤2 s 释放本任务网络资源 | 幂等、并发、截止与停止用确定性任务和真实任务分别检查；每秒持久化进度/自动重测次数均为 0 |

预算适用于新增卡片链路。不得把旧页面既有资源算作新增后再错误宣布回归，也不得把新增业务藏进旧 vendor、共享样式或其他进程而从增量报告中排除。实际带宽速率受测试时网络影响，正确性与同一任务引擎原始结果比较，不把两次不同测速的速率波动当作 UI 误差。

## FN01 冻结契约和三仓库基线

依赖：无。仓库：Q、F、P。

交付：卡片协议、数据与任务状态机、布局迁移规则、主题契约、测试输入、资源基线和版本兼容矩阵。

可测试目标：

1. **FN01-T01** 固定内置可安装元数据、已安装 manifest、组件导出、SDK、LuCI API 和 layout v4 的样例；有效、缺字段、未知版本和重复 ID 均有明确预期。
2. **FN01-T02** 固定 WAN 下载/上传完整结果的主时间，以及 NAT、IPv6 各自检测时间；明确未检测、有效的不可用结论、探测错误、旧结果和部分成功的区别。缺值不能转换为 0，读取不能刷新检测时间。
3. **FN01-T03** 固定任务状态与转换：idle、running、cancel_requested、succeeded、partial、failed、cancelled、interrupted；任务 ID、幂等键、服务实例身份、120 秒截止、并发和重启口径有可执行样例。
4. **FN01-T04** 固定旧 host/新插件、新 host/旧插件、缺少插件、缺少 LuCI、服务停用、注册与资产版本不一致的预期；兼容与拒绝范围不能留到联调临时决定。
5. **FN01-T05** 记录 Q/F/P 提交、独立卡片编译工具链、Vue/SDK 版本和既有测试实际结果；记录 x86_64 与 aarch64 测试设备、浏览器、资源预算的基线和测量方法。预算见本计划，任何基线期调整均须在依赖阶段开始前写明数值与原因。
6. **FN01-T06** 提供统一用例输入和报告格式；每个需求在覆盖矩阵有负责阶段。历史原型的通过结果不得充当外部卡片、主题三态或实机接入已通过。

完成判据：协议样例可由校验器验证，基线和预算已有实际记录，覆盖矩阵无缺项。没有实机基线时本阶段不能全部通过。

## FN02 统一正式页面和预览的主题机制

依赖：FN01。仓库：Q。

交付：复用 ThemeSelector 和 theme.ts 的预览入口、稳定的卡片 CSS 变量、能够实时变色的宿主弹层。

可测试目标：

1. **FN02-T01** 正式页面和 scripts/ui-design.sh 预览都提供 system/light/dark；移除预览的二态按钮和按普通路由变化强写 body 的逻辑。没有主题 URL 参数时保留已保存偏好；显式测试参数只通过统一主题服务应用。
2. **FN02-T02** 运行主题矩阵 TH01–TH06：显式浅深色覆盖系统颜色，system 随系统实时变化；保持 body[theme=normal] 的 LuCI 兼容口径和 data-quickstart-theme 的实际颜色。
3. **FN02-T03** 运行 TH07–TH08：刷新、跨标签页、本地存储不可用、LuCI 修改 body 主题均可正确处理；浏览器偏好不写入设备布局或 FastNet UCI。
4. **FN02-T04** 在卡片挂载区和统一弹层提供同一套 --qs-card-* 变量；覆盖面板、文字、次要文字、边框、强调、成功、警告、错误、焦点和禁用态。图标使用 currentColor，状态同时带文字。
5. **FN02-T05** 修正通用弹窗只在打开时复制一次颜色变量的问题；TH10 的弹窗持续打开期间系统变色后，卡片与弹窗的计算颜色都匹配宿主当前变量。
6. **FN02-T06** 主题服务的全局监听只保留一份；反复挂载选择器和弹层 50 次后，组件级订阅、DOM 与事件计数回到预热基线，原有主题测试继续通过。

完成判据：正式页面、预览和弹层的主题矩阵通过；主题来源唯一，未增加每张卡片的系统主题监听。

## FN03 建立共享运行时和外部卡片加载器

依赖：FN01、FN02。仓库：Q，F 的独立构建样例。

交付：card-runtime-v1、只读主题与展示上下文、通用 CardShell、独立编译样例和异步加载器。

可测试目标：

1. **FN03-T01** 独立编译一个外部 Vue 卡片，真实经 HTTP 动态导入并挂进首页组件树；Vue/SDK 显式解析到宿主共享入口。构建依赖图和网络请求证明没有第二份 Vue、Router、Pinia、ECharts 或完整 FastNet Web。
2. **FN03-T02** 未安装或未进入用户布局的模块不下载业务 JS；可安装目录只读取元数据。首屏外部卡片不阻塞原有卡片，首屏外加载与进入可视区加载均有请求顺序证据。
3. **FN03-T03** 同一已验证 entry URL 的并发请求复用加载 Promise 和组件定义；普通重排、主题变化及重新显示不追加时间戳 URL，不重复导入或初始化。失败允许显式重试，不永久缓存 rejected Promise。
4. **FN03-T04** 主题上下文为响应式只读快照，包含 preference/effective；TH09、TH11 中懒加载期间或运行期间切换主题不 remount、不重新请求业务数据、不提交新任务。
5. **FN03-T05** 资源 404、离线、慢响应、错误 MIME、无组件导出、ABI 不兼容只使本卡片进入有界错误态；重新发现最多一次，之后提供明确重试，其他模块可用。

## FN05 实现 FastNet 后台测速任务和结果存储

依赖：FN01。仓库：F。

交付：复用原测速引擎的后台任务、并发控制、幂等、截止与停止、最近成功结果和恢复状态。

可测试目标：

2. **FN05-T02** 双击、两个标签页、网络重试和同幂等键重放只产生一个任务；不同并发请求返回既有任务或明确 busy。卡片与已有 Web 中会占用测速资源的入口具有一致并发口径，原正常顺序体验可用。
3. **FN05-T03** 停止是幂等操作；进度迟到不会覆盖终态；请求取消与显式停止分开。超过 120 秒进入明确终态，停止或超时后 2 秒内释放本任务持有的网络/子任务资源。
4. **FN05-T04** 成功结果与同一 runId 的引擎输出一致；速率单位和 UTC 时间正确。部分成功仅更新成功项目，NAT/IPv6 失败不能刷新旧值时间或冒充新检测结论；失败和停止不覆盖有效旧结果。
5. **FN05-T05** 结果仅在状态转换或完成时有界持久化，进度不每秒写 Flash。模拟磁盘满、写入中断和权限失败，旧有效结果仍可读，新结果保存失败有明确状态。
6. **FN05-T06** FastNet 服务重启或设备重启后，既有运行任务标记 interrupted，不自动重新测速；最近成功结果仍可读。旧服务实例的迟到进度和 cancel 不能作用于新任务。
7. **FN05-T07** 任务、日志、结果数量有固定上限；读取摘要与历史不执行测速、不自动启动服务。完整 Web 原有的 WAN、LAN、NAT、IPv6 正常流程回归通过。

完成判据：确定性任务与故障测试通过，独立进程重启验证通过，真实 runId 的输出可核对。

## 实施前和最终交付检查

开始 FN01 时建立契约样例、实际测试入口、状态与预算记录，不能只把本计划的文字复制成 passed。各阶段的 `FNxx-Txx` 是必需验收 ID；测试实现可以合并共享 fixture，但报告必须逐项给出结果。

先完成 FN02 的主题统一，再让独立卡片使用 SDK；先完成 FN04 的布局协议，再把外部 ID 写入用户配置；先完成 FN05 的后台任务，再通过 controller 和卡片公开测速入口。

最终交付必须包含：三个仓库的对应修改与测试、独立卡片和 SDK 构建、两个架构候选包、真实 controller 与首页验证、全部主题和资源记录、布局与包升级回退步骤，以及本矩阵的逐项结果。未覆盖的声明支持架构、必需场景或预算都保留为未通过，不以模拟数据、截图数量或版本号替代。
