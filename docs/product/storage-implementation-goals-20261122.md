# 存储维护交互：目标、任务树与三轮验收

日期：2026-11-22。基线：`da034b6`。依据：[差距评审](storage-gap-analysis-20261122.md)。

## 目标与完成口径

本次沿用已确认的 quickstart 主题、四个工作区及右侧详情抽屉，补全日常维护和异常处理的产品原型。
每个建议必须有入口、状态、影响范围、后续动作、异常结果以及生产实现契约，不能只增加说明文字。
原型只使用示例数据，不执行磁盘、阵列、应用或外发通知操作；刷新重置，不冒充服务端持久任务。
现有 RAID 业务和接口仍复用，新增只读发现与维护设计不调用旧 Autofix 来伪装扫描。

验收分为三类：U 表示可操作的界面原型；C 表示生产实现契约及故障验收任务；H 表示尚需真实后端/目标机验证。
U/C 通过不等于 H 通过。生产写入和发布必须等其对应 H 验收完成。

## 最多三轮

1. 第一轮：建立目标与覆盖矩阵；完成原型交互、共享状态和技术契约，构建与浏览器检查。
2. 第二轮：针对第一轮发现的缺口修正，再验受影响路径并回归现有 RAID。
3. 第三轮：若仍有缺口，只修复已发现的问题并做最终检查；仍未通过项逐条保留，不声明全部通过。

最多三轮是修正上限，不要求为了凑次数重复改代码。每轮记录检查项、发现、修正、结果及证据。
本次不在真实业务盘做格式化、重建、满池或断电测试。
