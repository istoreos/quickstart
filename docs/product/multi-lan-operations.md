# 多 LAN 的兼容与运维约定

普通用户仍使用同一个设备管理页面。只有一个 LAN 时隐藏网络选择；有多个 LAN 时，桌面显示左侧网络列表，手机显示紧凑选择器。网桥、zone、引擎端口和版本号仅用于诊断。网络发现不会创建接口、DHCP 配置或执行实例。

## 目标和数据

- LAN 指逻辑网络，名称可以是 `lan`、`office` 等；物理端口不能冒充独立 LAN。同桥别名不能获得重复执行实例。
- 请求省略 `network` 仍只表示原 `lan`。原 `lan` 不存在时拒绝操作，不猜测其他网络。`all` 仅提供设备和流量总览。
- 设备由 `(networkId, deviceId)` 确定。同 MAC 在不同 LAN 的资料、历史、配额、分组和策略独立。
- 默认 LAN 保留原存储位置；其他 LAN 使用同目录下 `networks/<network>/`。不能把默认 LAN 数据复制为其他网络的初始策略。
- 网络停用、消失或接口身份变化后，重新读取作用域；旧版本和旧计划不能继续提交。未确认归属的设备保留可读记录。

## 原有用户如何升级

原 `lan → br-lan` 的页面和接口保持兼容，不要求用户重新设置资料、分组或额度。每个 NetPolicy 进程仍只管理一个接口，由 procd 命名实例提供多 LAN 隔离。旧 `main` 配置继续兼容；浏览器不选择端口、目录或任意服务地址。

旧断网规则不能区分手动暂停和配额封禁。按已确认的产品语义，取消旧额度、周期重置、改为仅提醒和后台分组计划均保留这类限制；应用启动时同步核对旧规则的网络绑定，后台每 30 秒检查接口变化；配额与分组写入复用同一个规则编译器。绑定未变化时不由恢复任务写配置或重载服务；失败时恢复原配置并报告错误。旧规则始终归属于原 LAN，来源和代次不被后台任务改写。界面提示用户明确恢复联网。恢复操作解除旧限制；新配额规则和新手动规则分别记录来源。设备离线不影响按持久化 MAC 识别旧规则。

新旧接口兼容有明确边界：新前端仅在网络清单接口返回不支持时回到旧单 LAN 模式；登录、权限、超时和服务错误不能触发回退。旧后端或旧引擎不具备额外 LAN 的能力，不能把请求转交默认 LAN 并报告成功。

## 能力范围

| 场景 | 行为 |
| --- | --- |
| 独立路由 LAN、明确 DHCP 绑定、可验证双向接入 | 按网络提供地址、策略、分组和流量能力 |
| 共享 zone 的多个 LAN | 按实际输入接口约束访问规则，不能只按 zone 和 MAC 编译 |
| 不重叠的 VLAN 接入 | 每个实例绑定自己的 VLAN 接口；父桥与子接口不能重复接管 |
| 外部 DHCP 或本机 DHCP 配置/实例不明确 | 保留观察；不开放未经确认的本机地址或路线写入 |
| 单臂、旁路、硬件卸载或执行路径无法确认 | 按实际能力报告受限或未验证，不能把已保存策略当作已验证执行 |
| 旧 eQoS/Bandix、单实例浮动网关 | 保留原默认 LAN 范围；额外 LAN 返回明确能力限制 |
| 重叠前缀、未知归属、VRF 等歧义拓扑 | 首版不宣称完整执行支持；不猜测目标 |

新手向导的原默认 LAN 语义保留。技术诊断中的设备名不会成为普通用户必须理解或填写的字段。

## 回退必须成套恢复

旧代码可能按 MAC 改写共享防火墙规则，不能直接对升级后的多 LAN 配置开放旧版写入。采用已验证的升级前备份恢复路径：

1. 升级前停止相关写入和后台执行，保存原 Quickstart、NetPolicy 二进制及 init 脚本、配置、Quickstart 数据、各配置指定的 NetPolicy 数据目录。记录版本及文件哈希。
2. 回退前再次停止相关进程，另存当前状态供诊断。恢复配套旧二进制、升级前配置和全部原数据目录，不把新多 LAN 文件混入旧状态。
3. 启动旧版本并核验默认设备资料、分组和策略版本；确认恢复后的实例配置与原二进制匹配，再开放写入。升级后新增 LAN 的策略不会通过旧版继续管理。

测试脚本 `scripts/ops/multi-lan-rollback-probe.py` 在任务所属网络、挂载和进程命名空间中运行实际新旧程序，验证升级后的独立资料，以及恢复前后的二进制/配置/数据文件哈希。其 netifd/rpcd 元数据为隔离测试输入，不代替真实认证或真实 DHCP 验收；真实固件 DHCP、procd 和数据包证据见 M05–M08。

## 验收状态与容量

固定资源门槛见 `docs/contracts/multi-lan.json`，不能按测量结果放宽。两台授权 4 GiB 测试机分别验证 1/2/4 LAN、每 LAN 256 台设备；完整应用预热 30 分钟后再运行至少 24 小时。CPU 包含已回收命令子进程，API 压测区间不冒充空闲采样；历史写入按实际原子替换事件计数。

是否通过以 `docs/archive/evidence/multi-lan/execution.json` 和 M10 结果为准。功能回归、短时容量或子模块长测通过，均不能代替完整候选的最终验收。此文不是发布完成声明。
