`http://192.168.9.215:5173/lan-device-management/`

## 1. 本轮要验证的问题

低保真原型需要验证：

1. 普通用户能否从“设备”进入并完成绝大多数任务；
2. 地址保留、上网路线、限速和联网权限能否围绕同一台设备自然组织；
3. 旁路由、浮动网关和 DHCP 是否在需要时可找到，又不会压迫普通用户；
4. 本机无 DHCP 分配权时，用户能否理解为什么设备路线不可编辑；
5. 中文设备备注名和 DHCP 网络主机名是否不会被误认为同一个字段；
6. 桌面端和移动端是否保持相同任务路径；
7. 图标自动推荐和手动选择是否既直观又不会掩盖真实品牌；
8. 浮动网关或设备限速未安装时，其他设备设置是否仍能完成。

## 2. 推荐方案

推荐采用“设备优先 + 详情抽屉”的结构：

```text
设备管理
├─ 设备                         默认首页，高频
│  └─ 设备详情                 桌面抽屉 / 移动端全屏
├─ 分组与计划                   中频
└─ 局域网设置                   低频、高影响
   ├─ 网络概况
   ├─ 地址分配
   ├─ 上网路线
   ├─ 带宽与统计
   └─ 诊断与高级
```

理由：

- 延续当前设备列表的认知入口；
- 不用先理解“网络规则”才能管理设备；
- 单设备操作在一个连续上下文中完成；
- 高影响设置仍有清晰边界；
- 适合路由器管理页面常见的桌面与手机混合使用。

原型同时保留两个对照方案用于评审：

- B：列表与详情双栏常驻，效率更高但小屏和低频用户负担更大；
- C：任务卡首页，更容易发现功能但设备列表不再是第一视觉焦点。

### 4.2 信息优先级

每行只承担五件事：

1. 这是什么设备；
2. 是否在线；
3. 当前地址；
4. 是否正在产生明显流量；
5. 是否存在非默认设置或异常。

默认不显示：

- MAC 完整值；
- DHCP Hostname；
- 原始厂商；
- 识别置信度；
- DHCP tag；
- 浮动网关节点细节；
- 没有意义的“全部正常”标签。

### 4.3 当前设置摘要

摘要最多显示两个高价值标签，优先级为：

1. 需要处理的异常；
2. 暂停联网；
3. 非默认上网路线；
4. 上网时段或流量额度；
5. 限速；
6. 地址保留。

超出时显示“另有 2 项”，点击后进入详情。默认路线不显示标签。

### 4.4 交互

- 点击设备行：打开设备详情；
- 点击“需要处理”：筛选真正需要行动的问题；
- 搜索：匹配备注名、观察到的名称、品牌、IP 和 MAC；
- “添加设备”：通过 MAC 创建“从未上线”设备；
- 刷新：只刷新设备观察数据，不打断正在编辑的表单；
- 列表自动更新时，不改变用户当前滚动位置和排序。

### 4.5 状态

- 首次加载：显示固定高度骨架，避免列表跳动；
- 空网络：解释设备上线后会自动出现；
- 搜索无结果：保留搜索词，提供清除；
- 部分数据源异常：仍展示设备，缺失字段显示“暂不可用”；
- 统计延迟：只在流量区域显示轻提示，不阻塞设备管理。

图标与品牌、类型是三个独立字段，图标显示按以下顺序解析：

1. 用户手动选择的图标；
2. 自动模式下，已识别厂商对应的原创或已授权视觉；
3. 没有厂商视觉时，使用设备类型图标；
4. 厂商和类型均未知时，使用通用电脑图标。

用户一旦手动选择，后续识别结果不得覆盖；“恢复自动推荐”会重新启用厂商与类型联动。图标选择器按类别分组，首屏优先显示当前类型和最近使用，不用一整面无结构的图标墙。品牌文字始终保留，厂商视觉不直接复制商标或产品渲染图。

### 5.4 路线选项规则

- “跟随网络默认”始终排第一；
- 只展示当前可达且适用于该设备的路线；
- 路线名称优先，IP 作为辅助信息；
- 浮动网关显示健康状态，但不显示主备协议细节；
- 自定义 IP 在选择后才显示输入框；
- 不允许选择设备自己的 IP；
- 不允许选择网段外、网络地址、广播地址或冲突地址；
- 保存后状态先显示“等待设备更新”，续租后再显示“已生效”。

### 5.5 无 DHCP 分配权

当本机不掌握 DHCP 分配权时，不显示一个灰掉但没有解释的表单，而显示只读结果和行动指引：

```text
上网路线                                         只读

这台设备的地址由主路由分配，无法在本机修改上网路线。
请在主路由中，将该设备的网关和 DNS 设置为：

本机地址     192.168.1.2                    [复制]

[了解为什么]
```

规则：

- 不提供“立即启用 DHCP”按钮；
- 不把旁路由身份当作唯一原因；
- 如果角色无法判断，仍使用相同的 DHCP 权限结果；
- “了解为什么”展开角色判断依据和风险说明；
- 未来配对管理入口只有在真正实现后才出现。

### 5.6 保存预览

```text
确认修改

客厅 ASUS 电脑
地址保留        自动获取 → 192.168.1.23
上网路线        网络默认 → 客厅旁路由

```

保存结果分开表达：

- 已保存，等待设备更新；
- 已生效；
- 无法验证；
- 应用失败，原设置已恢复；
- 应用失败，需要人工检查。

### 5.7 可选能力缺失

浮动网关和设备限速属于可选能力。前端统一消费以下状态，而不根据页面报错猜测：

```text
available       已安装且可以使用
disabled        已安装但未启用
not_installed   当前固件未安装
error           已安装但运行异常
unsupported     当前平台不支持
```

交互遵循“缺什么，只锁什么”：

- 浮动网关不可用时，只禁用“浮动网关”路线；默认、本机、上级、旁路由和指定 IP 仍能选择、预览和保存；
- 设备限速不可用时，只禁用上传、下载限速；联网权限、分组、上网时段和流量额度仍能编辑；
- 能力入口就在相关字段旁显示“需要安装”“需要启用”“运行异常”或“不支持”，不在页面顶部堆叠插件告警；
- 用户主动点击不可用能力时，打开能力说明层，说明用途、资源影响与安装动作；安装、启用或重试完成后返回原编辑页；
- 用户已经输入但尚未提交的其他字段需要保留，不能因为跳转安装而丢失草稿；
- 提交前重新检查能力状态；本次确实修改了不可用字段时阻止提交，并允许安装能力或撤销该项修改；不能静默只保存一半。

如果能力在已有配置生效后消失：

- 保留已有路线或限速值作为“期望配置”；
- 当前状态显示“无法执行”，并说明哪些规则仍在工作；
- 不静默改成默认路线、不删除限速值，也不把未执行状态显示成已生效；
- 能力恢复后先让用户确认或按照明确的自动恢复策略重新应用，并记录审计结果。

普通用户只看到“浮动网关能力”和“设备限速能力”；具体组件包名只在安装确认与专家诊断中出现。安装属于明确的系统变更，必须由用户主动确认，不自动执行。

### 7.2 网络概况与角色

系统输出的是“路由器上下文”，不是单一旁路由布尔值：

```text
网络概况

本机角色       旁路由
DHCP 分配权    由主路由负责
本机地址       192.168.1.2
上级网关       192.168.1.1
设备路线设置   只读

设备的地址由主路由分配。如需让设备经过本机，请在主路由上
把该设备的网关和 DNS 设置为 192.168.1.2。          [复制]
```

如果无法判断角色：

```text
本机角色       无法确定                         [确认角色]
DHCP 分配权    本机负责
设备路线设置   可配置
```

用户确认只影响产品解释和默认推荐，不绕过真实 DHCP 权限检查。

### 7.3 地址分配

常用设置：

- 是否由本机提供 DHCP；
- 地址池起止；
- 租期；
- 默认网关和 DNS 的结果摘要。

关闭 DHCP 是高影响操作，需要显示：

- 哪些设备将失去本机管理能力；
- 设备级地址保留和路线设置将变为只读；
- 网络中必须存在另一个 DHCP 服务器；
- 应用后如何重新进入管理页面。

### 7.4 上网路线管理

```text
上网路线                                         [添加路线]

网络默认       本机路由             使用中 · 21 台设备
客厅旁路由     192.168.1.2           正常 · 3 台设备
浮动网关       192.168.1.3           正常 · 5 台设备
下载机         192.168.1.8           不可达 · 0 台设备
```

路线目标统一模型：

- 名称；
- 类型：本机、上级、旁路由、浮动、自定义；
- 网关 IP；
- DNS 行为：当前固定“跟随路线”；
- 健康状态；
- 使用设备数；
- 能否删除及影响范围。

删除被使用的路线时，必须先选择这些设备的替代路线。

### 7.5 浮动网关

浮动网关作为一种路线目标管理：

```text
浮动网关

浮动地址       192.168.1.3
当前服务节点   客厅旁路由 B
备用接管节点   主路由 A
健康状态       正常
使用设备       5 台                              [查看]
最近切换       无
```

节点、优先级和检测参数放在编辑页；普通状态卡不暴露 VRRP、脚本或插件内部信息。

## 8. 三条关键用户路径

### 8.1 给一台设备指定旁路由

```text
设备首页
  → 点击设备
  → 网络与上网 / 编辑
  → 选择“客厅旁路由”
  → 看到“DNS 跟随路线”
  → 预览并保存
  → 已保存，等待设备更新
  → 设备续租后显示已生效
```

### 8.2 在无 DHCP 的旁路由上查看设备

```text
设备首页
  → 点击设备
  → 上网路线只读
  → 说明“地址由主路由分配”
  → 复制本机地址
  → 用户到主路由配置
```

流程中不出现“开启本机 DHCP”的诱导按钮。

### 8.3 设置中文设备备注

```text
设备详情
  → 编辑设备
  → 备注名输入“客厅电脑”
  → 保存到 Quickstart 设备资料
  → 列表立即显示新备注
```

整个流程不触碰 DHCP Hostname 和 dnsmasq。网络主机名只在“网络与上网 / 高级设置”中单独编辑。

### 9.5 保存事务

一次设备编辑可能同时包含：

- 地址保留；
- 网络主机名；
- 上网路线；
- 限速；
- 联网权限；
- 分组或计划例外。

后端需要提供统一的校验、预览、提交与回滚边界。备注名保存可以独立即时完成，但不能与 DHCP 写入混为同一字段。

## 10. 性能与路由器资源约束

- 设备首页只请求列表摘要，不为每台设备加载完整历史；
- 打开设备详情后再加载历史用量和诊断；
- 流量刷新批量返回，不能每台设备一次请求；
- 页面隐藏或抽屉关闭后停止高频采样；
- 历史数据必须有时间窗口、数量上限和磁盘上限；
- 列表只更新发生变化的设备，避免全表重建；
- 品牌、设备类型和路线名称由后端聚合，不在前端重复推断；
- 基础设备管理在统计插件异常时仍可工作。

## 11. 视觉与可用性约束

- 使用现有 Quickstart 色彩和组件体系，不引入第二套视觉语言；
- 卡片只用于表达明确的一组状态，避免每个字段一个卡片；
- 正常状态保持安静，异常和非默认结果才使用强调色；
- 危险操作使用文字说明，不只依赖红色；
- 品牌信息以文字为主、原创设备形态图标为辅，不使用厂商商标；
- 用户手动选择图标后必须稳定保留，并有明确的“恢复自动推荐”；
- 未命名设备使用与识别类型一致的通用形态，未知类型默认电脑形态；
- 所有图标必须有文字或无障碍名称，不能单靠图标传达状态。

## 12. 低保真验收标准

- 普通用户从设备首页最多三次操作可修改一台设备的上网路线；
- 中文备注名编辑流程不会出现 DHCP 或 dnsmasq 术语；
- 网络主机名明确限制字符并位于高级设置；
- 非默认路线在设备列表可见，默认路线不制造噪音；
- 无 DHCP 分配权时路线只读且说明下一步；
- 页面不会建议用户直接开启第二个 DHCP；
- 浮动网关既能在局域网设置管理，也能在使用它的设备上看到结果；
- 主路由、旁路由和角色不确定三种状态都有明确界面；
- 桌面端和移动端任务路径一致；
- 所有高影响修改都有预览、等待生效和失败恢复状态；
- 流量统计异常不会阻断设备列表和网络配置；
- 浮动网关缺失只会禁用对应路线，其他路线可继续保存；
- 设备限速缺失只会禁用限速字段，联网权限、时段和额度可继续保存；
- 已有配置所依赖的能力消失时，界面保留期望值并显示“当前无法执行”；
- 能力安装或恢复后返回原编辑任务，未提交草稿不会丢失；
- 用户无需理解 DHCP tag、option 3/6 或 UCI 即可完成主要任务。

## 13. 本轮建议确认项

1. 是否采用 A“设备优先 + 详情抽屉”作为正式布局方向；
2. 桌面详情使用抽屉、移动端使用全屏层是否合适；
3. 设备首页的非默认设置最多显示两个摘要标签是否合适；
4. 网络主机名放在“网络与上网 / 高级设置”是否合适；
5. 无 DHCP 权限时的只读说明是否足够清楚；
6. 局域网设置中的五个分区是否需要增删；
7. 图标优先级“手动选择 > 厂商视觉 > 类型 > 通用电脑”是否确认；
8. 可选能力缺失时采用局部降级、保留期望配置和用户主动安装是否确认。

确认后再输出视觉规格、前后端领域接口和实施里程碑，不直接把低保真原型代码当成生产代码。
